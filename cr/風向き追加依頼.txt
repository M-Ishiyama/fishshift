# Change Request: Ocean Map への海上風ベクトル（風向・風速）レイヤー追加

`DESIGN.md` の基本方針・制約（実データ検証の徹底、公開UIでのEarthdata認証不要化、欠損値の0埋め禁止、予報と過去観測の混同禁止）を厳守したうえで、**Ocean Map（S-02）の海流ベクトルレイヤーに「海上風（風向・風速）」を重ね合わせられる機能**を追加してください。

---

## 1. 変更目的
- 魚場候補海域の海況把握および海流との比較（順風／逆風、吹送流・潮目の理解）のため、`Ocean Map` 上で海流ベクトルと海上風ベクトル（風向・風速）を同時に重ね合わせ・個別ON/OFFできるようにする。

## 2. 使用データソースと取得・検証ルール（厳守）
1. **過去・月次／日次観測用（Ocean Map 対象）**
   - **NASA PO.DAAC** 提供の海上風ベクトルデータセットを調査・確定すること。
   - **第一候補**: `CCMP`（Cross-Calibrated Multi-Platform Ocean Vector Winds, Level 4, 0.25°格子, u10/v10成分）
   - **補助候補**: `MetOp ASCAT`（Level 2 沿岸12.5km / 25km 風ベクトル）
   - ※ `CYGNSS` はスカラー風速のみで低〜中緯度中心のため、北海道〜三陸海域の主データには採用しないこと。
   - ※ 実在するプロダクトID・バージョン・取得URL・ライセンスを実際に調査し、`data/metadata/datasets.yaml` および `provenance.json` に記録すること（未検証IDの埋め込み禁止）。
   - ※ NASAデータ取得は開発時バッチ（`scripts/prepare_nasa.py` または `scripts/prepare_wind.py`）に分離し、公開アプリ実行時に Earthdata Login を要求しないこと。取得不可の場合は保存済みスナップショットまたは明示した Simulation へフォールバックすること。
2. **航路試算予報用（Route Lab 対象）**
   - 従来の通り `Open-Meteo Weather API`（`wind_speed_10m`, `wind_direction_10m`）を使用し、NASA過去観測データと予報データを混同しないこと（UI上の出典・時刻ラベルを分ける）。

## 3. データモデル・前処理仕様
- `src/schemas.py` に風ベクトル表現（または `OceanObservation` / 格子データ型への追加）を定義する：
  - `wind_u_ms: float | None`（東西成分 m/s、東向き正）
  - `wind_v_ms: float | None`（南北成分 m/s、北向き正）
  - `wind_speed_ms: float | None`（風速 m/s）
  - `wind_from_deg: float | None`（気象学的風向：吹いて**くる**方向、北=0°時計回り）
  - `wind_to_deg: float | None`（ベクトル描画用：吹いて**いく**方向 = `(wind_from_deg + 180) % 360`）
- **単位・向きの変換ルールを明記**：
  - APIやNetCDFのメタデータ（`u10/v10` の向き、単位 `m/s` / `km/h` / `knots`）を実確認して統一する。
  - 海流の「流向（**向かう**方向 / TO）」と気象風向の「風向（**来る**方向 / FROM）」を取り違えないよう、内部変換関数と単体テストを用意する。
  - 欠損値（FillValue / 陸地マスク）は `None`（NaN）のまま保持し、`0` にしない。

## 4. UI / UX 要件（`src/ui/pages/ocean_map.py` & `about.py`）
1. **レイヤー切替コントロール**
   - `Ocean Map` のオーバーレイに以下を独立したチェックボックスとして設ける：
     - `Ocean Currents (海流ベクトル)`
     - `Surface Winds (海上風ベクトル)`
2. **視覚的干渉を防ぐ描画設計**
   - 海流ベクトル（実線・白/シアン系）と風ベクトル（破線または羽根記号・エメラルド系など明確に異なる色・線種）が重なって判読不能にならないよう、格子間引きのオフセット配置（例：奇数格子に海流、偶数格子に風）や視覚的差別化を行う。
   - マップ上の矢印は海流と比較しやすい向き（吹いていく方向 TO）で統一して描画し、凡例に「海流（流向・m/s）」「海上風（吹く向き・m/s）」を明記する。
   - ツールチップ／ホバー詳細では `風速 (m/s)` と `風向 (°から / FROM)` および `データ種別（Observed / Simulation）` を併記する。
3. **出典・制約表示（`S-06 About & Data`）**
   - 追加した NASA PO.DAAC 風データのプロダクトID、空間解像度（例: 0.25°）、観測期間、欠損扱い、沿岸域での解像度限界を追記する。

## 5. テスト要件（`tests/` に pytest 追加）
- `T-W01`: `(u10, v10)` から `wind_speed_ms`, `wind_from_deg`, `wind_to_deg` への変換テスト（例：西風 `u>0, v=0` のとき `wind_from_deg = 270°`, `wind_to_deg = 90°`）。
- `T-W02`: 単位変換テスト（km/h・knots → m/s）および欠損値が `0` にならず `None`/`NaN` のまま保持されるテスト。
- `T-W03`: 風レイヤーのデータ欠損時・取得失敗時にUIがクラッシュせず、欠損またはキャッシュフォールバック表示となるスモークテスト。

## 6. 完了条件
- 検証済みデータセット情報（または未取得理由と代替構成）を `README.md` と `data/metadata/datasets.yaml` に記録する。
- 既存および新規の `pytest` がすべてパスすること。
- `Ocean Map` で海流ベクトル＋海上風ベクトルの同時重ね合わせ、および個別ON/OFFが動作すること。
